---
title: Jellyfin player API
description: Use AIOStreams as a playback-only Jellyfin-compatible server for direct provider streams.
---

The optional Jellyfin player API lets Infuse Direct Mode and other compatible
players authenticate against an existing AIOStreams configuration, search the
user's search-capable metadata catalogs, and request AIOStreams' ordered stream
results using Jellyfin `PlaybackInfo` calls. It runs inside the normal
AIOStreams server; no bridge, sidecar, catalog import, or media proxy is
required.

Enable **Settings → API → Enable Jellyfin player API**, or set:

```env
ENABLE_JELLYFIN_API=true
```

Configure the player with this server URL:

```text
https://your-aiostreams.example/jellyfin
```

Use an AIOStreams configuration UUID (or configured alias) as the username and
that configuration's plain password as the password.

## Scope

This is an on-demand search and playback compatibility surface, not a
replacement Jellyfin library server. It exposes two empty virtual views so
players recognise movie and series search sources, but it never imports or
pre-populates a media library.

For title search to return results, the user's AIOStreams configuration must
include a search-capable movie/series catalog such as the TMDB addon. The same
configuration must include at least one addon that returns playable streams.

The main compatibility endpoints include:

```text
GET  /System/Info/Public
GET  /System/Info
POST /Users/AuthenticateByName
GET  /Users/Me
GET  /Users/{userId}/Views
GET  /UserViews
GET  /Items
GET  /Users/{userId}/Items
GET  /Search/Hints
GET  /Items/Resolve
GET  /Items/{itemId}
GET  /Shows/{seriesId}/Seasons
GET  /Shows/{seriesId}/Episodes
GET  /Items/{itemId}/Images/{imageType}
GET  /Items/{itemId}/PlaybackInfo
POST /Items/{itemId}/PlaybackInfo
GET  /Videos/{itemId}/stream[.{container}]
```

## Infuse Direct Mode

Add a Jellyfin media server in Infuse using the AIOStreams `/jellyfin` URL and
the AIOStreams configuration UUID (or alias) and plain configuration password.
Leave **Library Mode** disabled. Infuse sends searches to AIOStreams on demand;
the virtual views intentionally contain no browsable catalog entries.

```text
https://your-aiostreams.example/jellyfin
```

When Infuse sends `Items?SearchTerm=...`, AIOStreams locates the first
search-capable movie and/or series catalog in that user's configuration. Search
results are converted to Jellyfin item DTOs. Opening an item retrieves its
metadata, and opening an episode or movie invokes the user's normal AIOStreams
stream pipeline.

`PlaybackInfo` uses the normal AIOStreams fetch, filtering, deduplication,
sorting, Stream Expression Language, and result-limit pipeline. The dedicated
control-plane path returns before failover-chain construction, proxification,
external-download injection, next-episode precache, stream preload, URL ping,
or media transport.

Only final external HTTP(S) URLs are exposed. A source is omitted when it:

- points back to the AIOStreams origin;
- is already marked as proxied;
- requires request or response headers;
- is a magnet, NZB, archive, local file, or another non-HTTP transport.

The virtual `/Videos` URL validates a short-lived signed source grant and
responds with an HTTP `302` to the provider. AIOStreams does not request,
inspect, buffer, transcode, or relay the media bytes.

## Translating an external ID

The resolver extension converts an external identity into the stable 32-hex
item ID used by the official Jellyfin-shaped playback route:

```http
GET /jellyfin/Items/Resolve?Kind=Movie&Provider=Imdb&Id=tt1234567
X-Emby-Token: <access-token>
```

Episode example:

```http
GET /jellyfin/Items/Resolve?Kind=Episode&Provider=Tmdb&Id=98765&Season=2&Episode=3
X-Emby-Token: <access-token>
```

The same translation is available through an item query:

```http
GET /jellyfin/Items?AnyProviderIdEquals=Imdb.tt1234567&IncludeItemTypes=Movie
```

After reading the returned `Id`, request playback information normally:

```http
POST /jellyfin/Items/41494f4a010171000012d687ffffffff/PlaybackInfo
X-Emby-Token: <access-token>
Content-Type: application/json

{}
```

For player integrations that already own discovery, the compatibility parser
also accepts aliases such as `movie:imdb:tt1234567` and
`episode:imdb:tt7654321:2:3`. Stable 32-hex IDs are recommended for clients
that enforce Jellyfin's UUID-shaped item convention.

## Authentication

Authenticate with Jellyfin's standard request shape:

```http
POST /jellyfin/Users/AuthenticateByName
Content-Type: application/json

{
  "Username": "your-configuration-uuid",
  "Pw": "your-configuration-password"
}
```

The returned `AccessToken` is accepted through `X-Emby-Token`,
`X-MediaBrowser-Token`, `api_key`, or the Jellyfin `Authorization` token field.
It expires according to the configured API session lifetime. Passwords and
provider URLs are encrypted inside HMAC-signed tokens and are never logged.
